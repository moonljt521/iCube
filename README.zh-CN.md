# iCube

一款基于 SwiftUI 与 RealityKit 的 iOS 魔方竞速练习应用，支持 2/3/4 阶魔方、多套涂装皮肤、手势拧动、竞速计时与成绩统计，并内置可交互的图文 + 3D 演示教程。

## 功能特性

### 魔方练习

- **多阶支持**：2/3/4 阶魔方完整功能对等——手势、打乱、计时、还原判定、成绩记录全链路支持，阶数全局切换
- **官方规则打乱**：对齐 WCA 规则的随机打乱（2 阶 11 步 / 3 阶 20 步 / 4 阶 40 步，四阶含 2R 类内层转动），打乱步骤逐条回放动画
- **竞速计时**：按住待命、松手开表的竞速起手流程，支持 +2 / DNF 罚则
- **成绩统计**：最佳成绩、WCA 口径均值（ao5 / ao12）、按阶筛选的历史记录

### 手势交互

- **触摸即拧**：手指落在魔方贴纸上，沿滑动方向转动对应层；多指可同时转动互不相干的层
- **空域旋转**：手指落在魔方轮廓外拖动即旋转视角，两套手势按命中结果自动仲裁
- **双指捏合**：空白区域双指捏合缩放魔方（0.7x–1.5x，带阈值钳制）

### 涂装皮肤

- 内置 5 套皮肤：经典、竞速、霜面、糖果、曜石（配色灵感取自市面流行品牌涂装，色值与质感均经独立调整）
- 全局即时切换，无需重建场景；选择持久化保存

### 图文教程

- 三阶层先法 7 步 + 2-look OLL / PLL，覆盖 8 个阶段、20+ 个案型
- 每个案型配有 3D 魔方演示：自动摆出案型、逐步播放公式动画直至还原
- 案型与公式经过单元测试逐条校验（案型 = 还原态 + 公式逆，播放公式必可还原）
- 演示模型跟随全局阶数与当前皮肤

### 还原助手

- **拍照识别**：六个面各拍一张，自动读出当前状态并灌进展开图供复核。拍摄次序与角度随意——每个面独立识别，六个面靠穷举搜索拼回去
- **手动录入**：按标准展开图逐格填色，支持点涂与拖动连涂；六个中心块按标准配色预填，只需填 48 格
- **实时校验**：格数、每色个数逐项提示，填满且配平才允许求解
- **短解求解**：Kociemba 两阶段算法，随机打乱典型 20~24 步、单次约 26ms
- **文字 + 动画步骤**：编号步骤条随动画逐步高亮并自动滚动，支持重放、重置与三档速度
- 非法状态（单棱翻转、单角扭转、奇偶性错误）会被求解器拦下并给出中文说明

#### 拍照识别是怎么做的

从照片认魔方其实是两个独立的问题，难的那个不是颜色分类：

1. **颜色归类**——六个中心块在物理上必然互异，天然是六种颜色的锚点，直接拿它们作聚类种子，颜色空间就跟着这次拍摄走，自带标定。每一格的采样先按明度裁掉两端各 20% 再在**线性** RGB 里求平均（贴纸之间的塑料缝和高光正是把朴素平均拉偏的元凶）；整体再做白点校正，且校正在线性 RGB 里做——那是唯一能让对角校正精确成立的空间，这也是为什么经典的 XYZ von Kries 校正会残留约 9 个 Lab 单位误差，而这里残留为 0。
2. **朝向还原**——单张照片看不出这个面转了多少度，而只拍三个面也永远推不出另外三个面。所以朝向不是猜的：把 4⁶ 种朝向组合全部枚举，用可达性判定（中心块各就各位、每色恰好 9 个、棱角结构合法、棱朝向和与角朝向和、置换奇偶性）筛一遍，物理上恰好只有一种能通过，全程不到 20ms。

因为第二步是枚举而不是假设，拍摄次序、手机朝向、每个面转了多少度这些事都自动消掉了。

## 技术栈与架构

| 层级 | 技术 |
|------|------|
| UI | SwiftUI（iOS 18+） |
| 3D 渲染 | RealityKit（`RealityView` + 相机内容） |
| 持久化 | SwiftData（成绩记录）、UserDefaults（皮肤 / 阶数偏好） |
| 核心算法 | CubeKit（本地 SwiftPM 包） |
| 拍照识别 | CubeScan（本地 SwiftPM 包，零 UI 依赖）+ AVFoundation |
| 魔方求解 | CubeSolve（本地 SwiftPM 包）+ vendored [SwiftTB2PKit](https://github.com/edmw/SwiftTB2PKit) |

### CubeKit 内核设计

CubeKit 是与应用层完全解耦的纯 Swift 算法包，无 UIKit / RealityKit 依赖：

- **纯几何推导**：所有转动置换由整数格点坐标绕轴 90° 旋转实时推导，不含任何手抄置换表，正确性由几何不变量保证
- **N 阶泛化**：状态、层归属、记法（含 `2R` 内层与 `Rw` 宽层）、打乱均按阶数参数化；阶数由贴纸数量（6N²）反推，数据模型天然向后兼容
- **确定性打乱**：SplitMix64 种子化随机，同一 seed 可复现，符合 WCA 间隔规则（无同面连步、无同轴三连）

### 应用层设计

- **手势仲裁**：基于 raycast 命中结果的会话式多指手势追踪——贴纸命中转层、轮廓外旋转视角、空白双指捏合缩放，三者互不打断
- **场景复用**：同阶状态变化走场景内重建，换阶重建整个场景；材质按皮肤分桶缓存，换肤零重建成本
- **碰撞体约束**：贴纸碰撞体采用"整格覆盖、与表面齐平"策略，规避透视下误触邻面的经典问题
- **取景几何**：引导框是居中的正方形，而"绕中心转 90°"和"等比居中留边"都把中心映到中心。所以采样区域**永远**是相机帧里居中的正方形，代码刻意不去追帧被转了多少度——猜错方向会得到镜像，而镜像下游没有一步能补救；猜对方向得到的旋转则会被朝向枚举顺手消化掉。不追这个方向，就少一个能悄悄算错的地方
- **采样不占主线程**：相机回调跑在专用串行队列上，直接锁住 `CVPixelBuffer` 采 9 格（不复制整帧）；只有节流到约 10Hz 的结果才回主 actor。取景几何是**推**给那条队列的，不是让它回调时现算

### 求解层设计

CubeSolve 是夹在 CubeKit 与第三方求解库之间的一层薄适配，只做三件事：把 `CubeState` 译成 Kociemba 面位串、把底层错误译成本项目的错误面、把结果译回 `Algorithm`。求解算法本身由 vendor 进 `Vendor/SwiftTB2PKit` 的 Kociemba 两阶段实现提供。

- **面位约定**：外部记法面顺序为 `U R F D L B`，本项目 `Face` 的 rawValue 顺序是 `u d f b r l`，两者块顺序不同而每面内部的行列读法一致，故映射只是一次块重排
- **崩溃隔离**：底层 `TB2P.tables` 加载失败即 `fatalError`，调用方无法捕获。`CubeSolve.isAvailable` 先查资源是否在包内，缺失时抛错降级，不会把宿主 App 崩掉
- **表文件生命周期**：21MB 查找表由 `prepare()` 从 bundle 拷进 Caches 再加载。iOS 会清 Caches，所以**每次启动都要调**，不能只调一次
- **不保证最优解**：两阶段算法的剪枝表只是可采纳下界，下界高估时浅层搜索被整段剪掉，解可能长于最优。随机打乱实测 20~24 步、平均 22.6 步

### 拍照识别层设计

CubeScan 是零 UI 依赖的纯算法包——Lab 色彩换算、贴纸采样、聚类、朝向枚举、取景几何全部能在 macOS 上直接跑、直接测，不需要模拟器也不需要摄像头。应用层（`iCube/Scan/`）刻意做薄：只负责把帧喂进去、把结果接出来。

- **全程在 Lab 而不是 sRGB 里算**：sRGB 距离相等不等于"看起来差得一样多"（两个深蓝差 30 个码值几乎看不出，两个浅黄差同样多已经很明显）。Lab 还把明度和色度拆开，白点校正才谈得上"只除光照、不动颜色"
- **白平衡在线性 RGB 里做，不在 XYZ**：一束光打在同色贴纸上，在相机看来就是线性 RGB 三通道各乘一个系数，这正是相机白平衡在纠正的东西。经典的 von Kries 对角校正放在 XYZ 里只是它的近似——实测暖光下残留约 9 个 Lab 单位误差，线性 RGB 里是 0
- **截尾均值采样**：一格采样区里混着贴纸本体、黑色塑料缝和高光。按明度排序后两端各裁 20%，两头都去掉；平均在**线性 RGB** 里做，因为对 Lab 求平均没有意义
- **"每色恰好 9 个"是硬约束而不是启发式**：三阶每种颜色正好九个贴纸，所以簇大小不对时，把最骑墙的那个样本搬过去就行
- **朝向靠枚举**：4⁶ 种组合过一遍可达性判定。暴力在这里是划算的——绝大多数组合在第一两条棱上就被判出局，整轮扫完不到 20ms

## 工程结构

```
iCube/
├── project.yml              # XcodeGen 工程定义（唯一工程事实源）
├── CubeKit/                 # 核心算法包（SwiftPM）
│   ├── Sources/CubeKit/     # 魔方状态 / 转动 / 记法 / 打乱 / 朝向 / 面位编解码 / 可达性判定
│   └── Tests/CubeKitTests/  # 111 条单元测试
├── CubeScan/                # 拍照识别包（SwiftPM），依赖 CubeKit
│   ├── Sources/CubeScan/    # Lab 色彩 / 贴纸采样 / 聚类 / 面位拼装 / 取景几何
│   └── Tests/CubeScanTests/ # 48 条单元测试
├── CubeSolve/               # 求解适配包（SwiftPM），依赖 CubeKit 与 vendor 的求解库
├── Vendor/
│   └── SwiftTB2PKit/        # 第三方 Kociemba 两阶段求解器（MIT），改动见 VENDORED.md
├── iCube/                   # 应用层
│   ├── Practice/            # 练习页：场景、手势、计时、皮肤、演示棋盘
│   ├── Scan/                # 拍照识别：采集会话、预览桥接、编排、界面
│   ├── Solve/               # 还原助手：展开图录入、求解、步骤演示
│   ├── Tutorial/            # 教程：数据、演示模型、界面
│   ├── Stats/               # 成绩记录与统计
│   └── Assets.xcassets/     # App 图标等资源
├── iCubeTests/              # 应用层单元测试（68 条）
└── Tools/                   # 资源生成脚本（见下）
```

### 重新生成资源

```bash
# App 图标（1024px PNG）——产物与已入库的图标逐字节一致
swift Tools/make_icon.swift iCube/Assets.xcassets/AppIcon.appiconset/AppIcon.png

# 转动音效——注意：该脚本已被取代，详见脚本头部说明
swift Tools/make_sounds.swift <输出目录>
```

`make_icon.swift` 是现行图标的生成器。`make_sounds.swift` 仅作历史参考保留：
App 内三条 `turn_*.wav` 取自真实磁吸魔方录音，**无法**由该脚本复现。

## 快速开始

### 环境要求

- macOS 14+
- Xcode 26+（含 iOS 18 SDK；vendored 求解包的 `swift-tools-version` 为 6.2，需要 Swift 6.2 工具链）
- [XcodeGen](https://github.com/yonaskolb/XcodeGen)（`brew install xcodegen`）
- 真机调试需配置开发者签名（修改 `project.yml` 中的 `DEVELOPMENT_TEAM`）

### 构建运行

```bash
# 1. 生成 Xcode 工程（工程文件不入库，改动 project.yml 后需重新生成）
xcodegen generate

# 2. 打开工程
open iCube.xcodeproj

# 3. 选择目标设备，Cmd+R 运行
```

命令行构建真机包：

```bash
xcodebuild -project iCube.xcodeproj -scheme iCube \
  -destination 'generic/platform=iOS' -allowProvisioningUpdates build
```

### 运行测试

```bash
# CubeKit 算法包测试（macOS 直接跑，最快）
cd CubeKit && swift test

# CubeScan 识别包测试（纯算法，同样在 macOS 直接跑）
cd CubeScan && swift test

# CubeSolve 求解测试（端到端：随机打乱 → 求解 → 施加解 → 判定还原）
cd CubeSolve && swift test

# 全量测试（含应用层，需模拟器）
xcodebuild test -project iCube.xcodeproj -scheme iCube \
  -destination 'platform=iOS Simulator,name=iPhone 16'
```

> 求解相关测试在 debug 构建下慢约 20 倍（`-Onone`），要看真实耗时加 `-c release`。

> 本机 `sandbox-exec` 不可用时，SwiftPM 与 Xcode 都起不了宏/清单的插件宿主：
> `swift test` 加 `--disable-sandbox`，`xcodebuild` 加 `OTHER_SWIFT_FLAGS="-disable-sandbox"`。

## 测试策略

- **CubeKit（111 条）**：几何与贴纸索引不变量、各阶转动置换正确性、层深记法解析往返、宽层多阶展开语义、打乱可还原性与间隔规则、多阶随机转动颜色守恒、面位串双向转换，以及可达性判定（外层转动不破坏合法性；单棱翻转 / 单角扭转 / 两块互换一律被拒；朝向和靠穷举搜索验证而非手推规则）
- **CubeScan（48 条）**：sRGB↔Lab 往返对齐公开参考值、白点校正能抵消已知光照、黑缝与高光下的贴纸采样、日光 / 暖光 / 冷光 / 暗光加噪声下的自标定聚类、拍摄次序与朝向无关性、"每色 9 个"硬约束把骑墙样本拽回、4⁶ 朝向枚举只留下唯一合法解
- **CubeSolve（13 条）**：随机打乱端到端可还原、非法状态（单棱翻转 / 单角扭转）被拒、非三阶被拒、解串重解析一致、解只含外层转动
- **应用层（68 条）**：手势意图仲裁（含背向命中过滤）、场景构建与贴纸对账、教程案型/公式逐条校验、练习流程状态机、展开图坐标映射、还原录入的填色/校验/求解端到端，以及拍照 → 识别 → 灌进展开图这条接缝

## 设计细节

- 魔方姿态使用整数旋转矩阵（`Rotation`）累积，渲染时一次性转换为四元数，彻底避免浮点漂移导致的贴纸错位
- 层归属判定基于块中心在面法向上的投影（内层即 `depth` 记法），与基准面朝向无关
- 计时器使用 `TimelineView` 按帧驱动，暂停态零开销
